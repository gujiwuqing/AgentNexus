# knowledge-seed —— 知识库种子内容

这里是为 AgentNexus 准备的**真实工作向**知识库内容（软件工程交付领域，通用可复用），
用于填充知识库、给 Agent 做 RAG 检索增强。全部为 Markdown，标题层级清晰，适配系统的"结构感知分块"。

## 目录结构

| 目录 | 对应知识库 | 内容 | 建议挂载给 |
| --- | --- | --- | --- |
| `01-工程规范库/` | 工程规范库 | 代码评审清单、编码规范、Git 与提交规范、API 设计准则 | 代码评审员、技术方案师 |
| `02-测试与质量库/` | 测试与质量库 | 测试设计方法论、用例模板、缺陷分级、发布准入清单 | 测试设计师 |
| `03-需求与产品库/` | 需求与产品库 | PRD 模板、用户故事与验收标准、需求优先级框架 | 需求分析师、产品运营策划 |
| `04-架构与技术选型库/` | 架构与技术选型库 | 架构决策记录 ADR、技术选型对比方法、非功能性需求清单 | 技术方案师、深度研究员 |

## 前置条件

**必须先在应用「设置」页配置 embedding 模型**（如 `text-embedding-3-small`），否则文档无法索引、检索测试会返回 424。

## 导入方式一：批量脚本（推荐）

1. 启动开发服务器：`pnpm run dev`
2. 运行脚本（用你的登录账号密码）：

```bash
SEED_EMAIL=you@example.com SEED_PASSWORD=yourpassword pnpm run seed:knowledge
```

脚本会：为每个子目录创建同名知识库（去掉数字前缀）→ 上传该目录下所有 `.md` → 服务端自动分块 + embedding。

可选环境变量：
- `SEED_BASE_URL`（默认 `http://localhost:3000`）
- `SEED_EMBEDDING_MODEL`（建库时指定 embedding 模型，不填用全局设置）
- `SEED_CHUNK_SIZE`（默认 800）、`SEED_CHUNK_OVERLAP`（默认 100）

脚本**幂等**：同名知识库复用、已存在文档跳过，可安全重复运行。

## 导入方式二：手动上传

进入「知识库」→ 新建知识库 → 详情页「文档」Tab → 拖拽上传对应目录下的 `.md` 文件。

## 导入之后

1. 到各 Agent 详情页，在「知识库」区域勾选关联对应知识库。
2. 用知识库详情页的「检索测试」验证效果（输入一个真实问题看能否命中相关片段）。
3. 详细的使用方法见 [`docs/Agent与工作流实战攻略.md`](../docs/Agent与工作流实战攻略.md)。

## 分块参数说明

这些文档标题层级清晰、含清单与表格，`chunkSize≈800 / overlap≈100` 较合适：既能让一个"章节要点"落在同一分片，又保留跨片上下文。若检索命中过碎，可调大 chunkSize 后重新索引。
